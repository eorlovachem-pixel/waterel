## 1. Списки

Список — упорядоченная изменяемая коллекция. Элементы лежат подряд, у каждого есть индекс. Индексация начинается с `0`. Список можно менять: добавлять, удалять, заменять элементы. В одном списке разрешены значения разных типов.

```python
numbers = [1, 2, 3, 4]
names = ["Alice", "Bob", "Charlie"]
mixed = [1, "hello", 3.14, True]
empty_list = []
```

| Строка | Что означает каждый символ |
|---|---|
| `numbers = [1, 2, 3, 4]` | Имя `numbers` связывается с новым списком. Квадратные скобки `[ ]` создают список. Запятые разделяют элементы. `1, 2, 3, 4` — целые числа типа `int`. |
| `names = ["Alice", "Bob", "Charlie"]` | Список строк. Кавычки `"..."` задают строковый литерал `str`. |
| `mixed = [1, "hello", 3.14, True]` | Четыре разных типа: `int`, `str`, `float` (`3.14` — число с точкой), `bool` (`True`). Python это разрешает, потому что список хранит ссылки на объекты, а не однородный блок памяти. |
| `empty_list = []` | Пустой список. Длина `0`, обращаться по индексу нельзя. |

```python
numbers.append(5)
first = numbers[0]
numbers[0] = 10
part = numbers[1:3]
length = len(numbers)
```

| Строка | Разбор |
|---|---|
| `numbers.append(5)` | Метод `append` добавляет один элемент **в конец**. После этого список равен `[1, 2, 3, 4, 5]`. Скобки `()` — вызов метода, `5` — аргумент. Точка `.` обращается к методу объекта. |
| `first = numbers[0]` | Квадратные скобки после имени — индексация. Индекс `0` — первый элемент, значение `1`. |
| `numbers[0] = 10` | Присваивание по индексу **заменяет** элемент, список не копируется. Теперь `[10, 2, 3, 4, 5]`. |
| `part = numbers[1:3]` | Срез. Левая граница `1` включается, правая `3` **не включается**. Берутся индексы 1 и 2: `[2, 3]`. Это новый список, исходный не меняется. |
| `length = len(numbers)` | Встроенная функция `len` возвращает число элементов. Здесь `5`. |

Почему срез не включает правую границу: длина среза равна `stop - start`. Срез `a[i:i+k]` всегда содержит ровно `k` элементов, если они есть.

## 2. Словари

Словарь хранит пары «ключ — значение». Ключ уникален. С Python 3.7 порядок пар — порядок добавления. Поиск по ключу в среднем за постоянное время: ключ прогоняется через хеш-функцию, по хешу находится ячейка.

```python
config = {"learning_rate": 0.001, "batch_size": 32, "epochs": 10}
model_info = {"name": "SimpleNet", "layers": 3, "activation": "ReLU"}
empty_dict = {}
```

| Символ | Смысл |
|---|---|
| `{ }` | Литерал словаря. Пустые `{}` — пустой словарь, не пустое множество. Пустое множество создаётся через `set()`. |
| `"learning_rate": 0.001` | Ключ-строка и значение-дробь. Двоеточие отделяет ключ от значения. |
| Запятые | Разделяют пары. |

Ключи здесь — строки, потому что так параметры модели читаются по имени: скорость обучения, размер пакета, число эпох.

```python
config["device"] = "cuda"
config["epochs"] = 20
lr = config["learning_rate"]
if "batch_size" in config:
    print("Размер пакета задан")
keys = list(config.keys())
values = list(config.values())
```

| Строка | Разбор |
|---|---|
| `config["device"] = "cuda"` | Ключа `device` ещё не было. Присваивание **добавляет** новую пару. |
| `config["epochs"] = 20` | Ключ уже был. Присваивание **перезаписывает** значение `10` на `20`. Старое значение теряется. |
| `lr = config["learning_rate"]` | Чтение по ключу. Если ключа нет, будет `KeyError`. |
| `"batch_size" in config` | Оператор `in` для словаря проверяет **ключ**, не значение. |
| `if ...:` | Если условие истинно, выполняется блок с отступом в 4 пробела. |
| `print(...)` | Печатает строку и перевод строки. |
| `config.keys()` | Представление всех ключей. Это не список, пока его не превратить. |
| `list(...)` | Конструктор списка копирует ключи в обычный список. |
| `config.values()` | Аналогично для значений. Есть ещё `items()` — пары `(ключ, значение)`. |

## 3. Кортежи

Кортеж — упорядоченная **неизменяемая** коллекция. После создания нельзя заменить, добавить или удалить элемент. Читать по индексу и делать срез можно. Неизменяемость нужна, когда набор должен остаться целым: координата точки, цвет, ключ словаря.

```python
point = (3, 4)
rgb_color = (255, 128, 0)
single_element = (42,)
empty_tuple = ()
```

| Строка | Разбор |
|---|---|
| `(3, 4)` | Круглые скобки и запятая создают кортеж из двух `int`. |
| `(255, 128, 0)` | Три канала цвета, каждый от 0 до 255. |
| `(42,)` | Кортеж из одного элемента. **Запятая обязательна.** Без неё `(42)` — это просто число в скобках, тип `int`. |
| `()` | Пустой кортеж. |

```python
x = point[0]
x, y = point
cache = {(3, 4): "origin quadrant"}
my_list = [1, 2, 3]
my_tuple = tuple(my_list)
```

| Строка | Разбор |
|---|---|
| `point[0]` | Индексация как у списка. `x` становится `3`. Присвоить `point[0] = 1` нельзя: `TypeError`. |
| `x, y = point` | Распаковка. Слева две переменные, справа кортеж той же длины. `x = 3`, `y = 4`. Если длин не совпадут — `ValueError`. |
| `{(3, 4): "origin quadrant"}` | Кортеж может быть ключом словаря, потому что он неизменяемый и хешируемый. Список ключом быть не может. |
| `tuple(my_list)` | Встроенный конструктор `tuple` копирует элементы списка в новый кортеж `(1, 2, 3)`. Исходный список остаётся списком. |

## 4. Условный оператор `if`

`if` выбирает один блок кода по логическому условию.

```python
x = 10
if x > 5:
    print("x больше 5")
elif x == 5:
    print("x равен 5")
else:
    print("x меньше 5")
```

| Часть | Смысл |
|---|---|
| `x = 10` | Переменная `x` получает целое `10`. Одиночный `=` — присваивание, не сравнение. |
| `if x > 5:` | Условие. `>` сравнивает числа и даёт `True` или `False`. Двоеточие открывает блок. |
| отступ | Блок принадлежит ближайшему заголовку. В ноутбуке отступ — 4 пробела. |
| `elif x == 5:` | «Иначе, если». Проверяется только если предыдущие условия ложны. `==` — сравнение на равенство. |
| `else:` | Всё оставшееся. Условия нет. |
| порядок | Сверху вниз выполняется **первая** истинная ветка, остальные пропускаются. Здесь печатается «x больше 5». |

## 5. Цикл `for`

`for` повторяет блок для каждого элемента последовательности.

```python
for i in range(3):
    print("Итерация", i)

fruits = ["Apple", "Banana", "Orange"]
for fruit in fruits:
    print("Ем", fruit)
```

| Часть | Смысл |
|---|---|
| `for i in ...:` | На каждой итерации имя `i` получает следующий элемент. |
| `range(3)` | Последовательность `0, 1, 2`. Правая граница не входит. `range(start, stop, step)` задаёт начало, конец и шаг. |
| `print("Итерация", i)` | Несколько аргументов печатаются через пробел. |
| `for fruit in fruits:` | Перебор самого списка. `fruit` по очереди равен `"Apple"`, `"Banana"`, `"Orange"`. Индекс здесь не нужен. |

```python
for idx, fruit in enumerate(fruits):
    print(f"{idx}: {fruit}")

names = ["Alice", "Bob"]
ages = [25, 30]
for name, age in zip(names, ages):
    print(f"{name} — {age} лет")
```

| Часть | Смысл |
|---|---|
| `enumerate(fruits)` | Даёт пары `(номер, элемент)`, нумерация с нуля: `(0, "Apple")`, `(1, "Banana")`, `(2, "Orange")`. |
| `idx, fruit` | Распаковка каждой пары в две переменные. |
| `f"{idx}: {fruit}"` | f-строка. Выражения в `{ }` вычисляются и вставляются в текст. |
| `zip(names, ages)` | Склеивает списки **попарно**, пока не кончится более короткий: `("Alice", 25)`, `("Bob", 30)`. |
| `for name, age in ...` | Снова распаковка пары. |

## 6. Контекстный менеджер `with`

`with` гарантирует вход в контекст и выход из него, даже если внутри возникла ошибка. Для файла это значит: открыть, выполнить блок, закрыть файл в любом случае.

```python
with open("example.txt", "w") as f:
    f.write("Hello, World!")
```

| Часть | Смысл |
|---|---|
| `open("example.txt", "w")` | Открывает файл. Первый аргумент — путь. `"w"` — режим записи: файл создаётся или **обнуляется**. `"r"` — чтение, `"a"` — дозапись. |
| `as f` | Результат (`файловый объект`) кладётся в имя `f`. |
| `f.write(...)` | Записывает строку в файл. Кавычки вокруг текста — литерал `str`. |
| выход из блока | Вызывается закрытие файла. Без `with` файл надо закрывать через `f.close()`, и при исключении это легко забыть. |

В PyTorch тот же механизм используется в `with torch.no_grad():`: на входе отключается построение графа производных, на выходе режим возвращается обратно. Это экономит память при проверке модели.

## 7. Функция

Функция — именованный блок, который можно вызывать много раз с разными аргументами.

```python
def greet(name):
    return f"Привет, {name}!"

print(greet("Anna"))
```

| Часть | Смысл |
|---|---|
| `def` | Ключевое слово «определить функцию». Пока строка выполняется, функция только создаётся, тело не бежит. |
| `greet` | Имя функции. |
| `(name)` | Список параметров. `name` — обязательный параметр: вызов без аргумента даст `TypeError`. |
| `return` | Немедленно заканчивает функцию и отдаёт значение вызывающему коду. Без `return` функция вернёт `None`. |
| `f"Привет, {name}!"` | В строку подставляется то, что лежит в `name`. |
| `greet("Anna")` | Вызов. `"Anna"` попадает в параметр `name`. Результат — строка `"Привет, Anna!"`, её печатает `print`. |

## 8. Класс и метод

Класс — чертёж объектов. Объект хранит данные (атрибуты) и действия (методы).

```python
class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        return f"{self.name} говорит «Гав!»"

my_dog = Dog("Sharik")
print(my_dog.bark())
```

| Часть | Смысл |
|---|---|
| `class Dog:` | Объявление класса. Тело класса — с отступом. |
| `def __init__(self, name):` | Конструктор. Имя с двойными подчёркиваниями — специальный метод. Python вызывает его сам при `Dog(...)`. |
| `self` | Ссылка на **конкретный** создаваемый объект. В вызов его передаёт сам Python, в скобках при создании его не пишут. |
| `self.name = name` | Атрибут экземпляра. У каждого объекта своё поле `name`. |
| `def bark(self):` | Обычный метод. Первый параметр снова `self`, чтобы метод видел данные своего объекта. |
| `Dog("Sharik")` | Создание экземпляра: выделяется объект, вызывается `__init__(объект, "Sharik")`. |
| `my_dog.bark()` | Вызов метода. Python превращает это в `Dog.bark(my_dog)`. Печатается `Sharik говорит «Гав!»`. |

Тот же приём в PyTorch: `model = MyNet()` создаёт экземпляр, слои лежат в `self`, а проход данных описывает метод `forward`.

Отдельный короткий пример методов без состояния:

```python
class Calculator:
    def add(self, a, b):
        return a + b

    def multiply(self, a, b):
        return a * b

calc = Calculator()
print(calc.add(2, 3))
print(calc.multiply(2, 3))
```

`add` возвращает сумму, `multiply` — произведение. `self` здесь не используется для хранения данных, но параметр обязателен: метод всё равно привязан к объекту. Результаты: `5` и `6`.

## 9. Три принципа ООП

### 9.1. Инкапсуляция

Данные и операции над ними собраны в одном объекте. Снаружи работают с методами, а не правят поля вразнобой.

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount
        print(f"{self.owner} пополняет счёт на {amount}. Баланс: {self.balance}")

    def withdraw(self, amount):
        if amount <= self.balance:
            self.balance -= amount
            print(f"{self.owner} снимает {amount}. Баланс: {self.balance}")
        else:
            print("Недостаточно средств!")

acc = BankAccount("Alice", 100)
acc.deposit(50)
acc.withdraw(30)
```

| Часть | Смысл |
|---|---|
| `balance=0` | Параметр со значением по умолчанию. `BankAccount("Alice")` создаст счёт с нулём. |
| `self.balance += amount` | Сокращение для `self.balance = self.balance + amount`. |
| `amount <= self.balance` | Снятие разрешено только если денег хватает. |
| `self.balance -= amount` | Уменьшение баланса. |
| `BankAccount("Alice", 100)` | Владелец Alice, баланс 100. |
| `deposit(50)` | Баланс становится 150. |
| `withdraw(30)` | Баланс становится 120. |

Инкапсуляция здесь в том, что правило «нельзя снять больше, чем есть» живёт внутри класса. Вызывающий код пишет `acc.withdraw(30)` и не дублирует проверку.

### 9.2. Наследование

Дочерний класс получает атрибуты и методы родителя и может заменить часть из них.

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def like(self):
        return "есть"

    def speak(self):
        return "Звук"

class Dog(Animal):
    def speak(self):
        return "Гав!"

dog = Dog("Bobik")
print(dog.name, "говорит", dog.speak())
print(dog.name, "любит", dog.like())
```

| Часть | Смысл |
|---|---|
| `class Dog(Animal):` | `Dog` наследует `Animal`. В скобках — родитель. |
| свой `speak` | Переопределение. У собаки звук `"Гав!"`, общий метод родителя для этого объекта больше не используется. |
| `like` не переопределён | Берётся версия родителя, возвращает `"есть"`. |
| `Dog("Bobik")` | Своего `__init__` у `Dog` нет, поэтому вызывается `Animal.__init__`, и появляется `self.name`. |
| печать | `Bobik говорит Гав!` и `Bobik любит есть`. |

В PyTorch модель наследует `nn.Module` и получает регистрацию слоёв, перенос на GPU, обход параметров. Свой код пишется в `__init__` и `forward`.

### 9.3. Полиморфизм

Один и тот же вызов работает с объектами разных классов. Какой код выполнится, решается по фактическому типу объекта.

```python
class LinearModel:
    def save(self, path):
        print(f"Сохраняем линейную модель в {path}")

class CNNModel:
    def save(self, path):
        print(f"Сохраняем свёрточную сеть в {path}")

class TransformerModel:
    def save(self, path):
        print(f"Сохраняем трансформер в {path}")

def backup_model(model, filename):
    model.save(filename)

models = [
    LinearModel(),
    CNNModel(),
    TransformerModel()
]

for model in models:
    backup_model(model, "checkpoint.pth")
```

`backup_model` не проверяет тип. Она вызывает `model.save`. У трёх классов метод называется одинаково, реализации разные. Цикл трижды вызывает одну функцию и получает три разные печати. Это и есть полиморфизм: общий интерфейс `save(path)`, разное поведение.

`LinearModel()` без аргументов вызывает `__init__`, которого в классе нет. Срабатывает конструктор `object`, объект создаётся пустым, этого достаточно, потому что состояние классу не нужно.

## 10. PyTorch: устройство и родительский конструктор

```python
import torch
torch.cuda.is_available()
```

`import torch` загружает библиотеку. `torch.cuda.is_available()` возвращает `True`, если сборка PyTorch видит совместимый GPU NVIDIA и драйвер CUDA. Иначе `False`, и все тензоры остаются на CPU.

Модель обязана начать конструктор с инициализации родителя:

```python
from torch import nn

class MyNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.layer = nn.Linear(10, 1)
```

| Часть | Смысл |
|---|---|
| `from torch import nn` | Импорт модуля нейросетей. `nn.Linear`, `nn.ReLU`, `nn.Module` живут здесь. |
| `class MyNet(nn.Module)` | Наследование от базового класса всех моделей PyTorch. |
| `super().__init__()` | Вызов конструктора родителя. `super()` находит следующий класс в цепочке наследования. Без этого вызова у объекта не будет внутреннего словаря параметров и подмодулей. |
| `nn.Linear(10, 1)` | Полносвязный слой: 10 входов, 1 выход. Формула одного примера: `y = x W^T + b`. Матрица весов имеет форму `(1, 10)`, смещение `b` — форму `(1)`. Веса — обучаемые тензоры. |
| `self.layer = ...` | Присваивание слоя атрибуту `nn.Module` **регистрирует** его. Позже `model.parameters()` отдаст эти веса оптимизатору, а `model.to(device)` перенесёт их на GPU. Если положить слой в обычную локальную переменную, регистрация не произойдёт. |

## 11. Прямой проход `forward`

```python
class SimpleNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(10, 5)
        self.fc2 = nn.Linear(5, 1)

    def forward(self, x):
        x = self.fc1(x)
        x = nn.ReLU()(x)
        x = self.fc2(x)
        return x

model = SimpleNet()
input_data = torch.randn(1, 10)
output = model(input_data)
```

| Строка | Разбор |
|---|---|
| `self.fc1 = nn.Linear(10, 5)` | Первый слой: вектор длины 10 превращается в вектор длины 5. «fc» — fully connected, полносвязный. |
| `self.fc2 = nn.Linear(5, 1)` | Второй слой: 5 чисел сжимаются в 1. |
| `def forward(self, x)` | Обязательное имя. Сюда PyTorch отдаёт входной тензор. |
| `x = self.fc1(x)` | Слой — вызываемый объект. Внутри матричное умножение и прибавление смещения. Имя `x` переиспользуется: старый тензор заменяется новым. |
| `nn.ReLU()(x)` | Два вызова подряд. `nn.ReLU()` создаёт модуль активации, сразу за ним `(x)` применяет его. ReLU считает `max(0, значение)` поэлементно: отрицательные зануляются, положительные остаются. Это вносит нелинейность. Без неё два линейных слоя схлопнулись бы в один линейный. |
| `return x` | Выход сети, форма `(1, 1)` для одного примера. |
| `SimpleNet()` | Слои создаются один раз, в конструкторе, а не внутри `forward`. Если создавать их в `forward`, на каждом проходе будут новые случайные веса, и обучение не накопится. |
| `torch.randn(1, 10)` | Случайный тензор из стандартного нормального распределения (среднее 0, дисперсия 1). Форма `(1, 10)`: один пример, 10 признаков. |
| `model(input_data)` | Вызывать надо сам объект, не `model.forward(...)` напрямую. `__call__` у `nn.Module` вызывает хуки и затем `forward`. |

## 12. `__len__`, `__getitem__` и `DataLoader`

Специальные методы Python вызывает сам.

- `len(obj)` превращается в `obj.__len__()`.
- `obj[i]` превращается в `obj.__getitem__(i)`.

Набор данных для обучения обязан уметь сказать, сколько в нём примеров, и отдать пример по номеру.

```python
from torch.utils.data import Dataset, DataLoader

class MyDataset(Dataset):
    def __init__(self, data, labels):
        self.data = data
        self.labels = labels

    def __len__(self):
        return len(self.data)

    def __getitem__(self, idx):
        return self.data[idx], self.labels[idx]

import torch
X = torch.randn(100, 5)
y = torch.randint(0, 2, (100,))

dataset = MyDataset(X, y)
dataloader = DataLoader(dataset, batch_size=10, shuffle=True)

for batch_x, batch_y in dataloader:
    print("Форма пакета признаков:", batch_x.shape)
    print("Форма пакета меток:", batch_y.shape)
    break
```

| Часть | Смысл |
|---|---|
| `class MyDataset(Dataset)` | Наследование от базового набора PyTorch. |
| `self.data`, `self.labels` | Ссылки на тензоры сохраняются в объекте. Копирования всей матрицы нет. |
| `__len__` | Возвращает 100, потому что в `X` сто строк. `DataLoader` по этой длине понимает, сколько шагов в эпохе. |
| `__getitem__` | Возвращает **кортеж** из одной строки признаков и одной метки. Индекс `idx` приходит от загрузчика. |
| `torch.randn(100, 5)` | 100 примеров, 5 признаков, нормальный шум. |
| `torch.randint(0, 2, (100,))` | Целые случайные метки. Нижняя граница 0 входит, верхняя 2 не входит, поэтому значения только `0` и `1`. Форма `(100,)` — вектор, запятая в кортеже обязательна, иначе `(100)` было бы просто числом. |
| `DataLoader(..., batch_size=10, shuffle=True)` | Собирает примеры в пакеты по 10. `shuffle=True` перед эпохой перемешивает индексы, чтобы пакеты не были всегда одинаковыми. |
| `for batch_x, batch_y in dataloader` | На каждой итерации загрузчик берёт 10 индексов, вызывает `__getitem__` для каждого и склеивает результаты в тензоры. |
| формы | `batch_x` имеет форму `(10, 5)`, `batch_y` — форму `(10,)`. |
| `break` | Выход после первого пакета. В примере достаточно показать форму, полный проход по 10 пакетам не нужен. |

Эпоха — один полный проход по обучающей выборке. При 100 примерах и пакете 10 получается 10 итераций на эпоху.

## 13. Практическое задание 1. Класс `DotCalculator`

Условие: на вход две точки в виде кортежей. Нужно посчитать длину отрезка и угловой коэффициент прямой. Оба числа округлить до двух знаков после запятой.

Обозначения. Первая точка `(x1, y1)`, вторая `(x2, y2)`.

- Разности: `dx = x2 - x1`, `dy = y2 - y1`.
- Длина по теореме Пифагора: `L = sqrt(dx² + dy²)`.
- Угловой коэффициент: `k = dy / dx`. Это тангенс угла наклона прямой к оси абсцисс. Если `dx = 0`, прямая вертикальная, частное не определено.

```python
from math import hypot

class DotCalculator:
    def __init__(self, dot1, dot2):
        # Для обеих формул нужны разности координат.
        self.dx = dot2[0] - dot1[0]
        self.dy = dot2[1] - dot1[1]

    def length(self):
        # Длина отрезка — гипотенуза с катетами |dx| и |dy|.
        return round(hypot(self.dx, self.dy), 2)

    def slope(self):
        # При равных координатах x угловой коэффициент не определён.
        if self.dx == 0:
            return None
        return round(self.dy / self.dx, 2)

segment = DotCalculator((1, 1), (4, 5))
print(f"Длина отрезка {segment.length():.2f}")
print(f"Угловой коэффициент {segment.slope():.2f}")
```

| Строка | Разбор до символа |
|---|---|
| `from math import hypot` | Из стандартного модуля `math` берётся одна функция. `hypot(a, b)` считает `sqrt(a*a + b*b)` аккуратно, без переполнения промежуточных квадратов. |
| `class DotCalculator:` | Класс калькулятора двух точек. Состояние объекта — две разности, сами точки после конструктора не хранятся, они больше не нужны. |
| `def __init__(self, dot1, dot2):` | Два аргумента — кортежи координат. |
| `dot2[0] - dot1[0]` | Абсцисса второй точки минус абсцисса первой. Для примера `4 - 1 = 3`. |
| `dot2[1] - dot1[1]` | Ординаты: `5 - 1 = 4`. |
| `self.dx`, `self.dy` | Поля экземпляра. Методы `length` и `slope` читают уже посчитанные разности и не принимают точки заново. |
| `hypot(self.dx, self.dy)` | `hypot(3, 4) = 5.0`, классический египетский треугольник. Знак разности не важен: квадрат его убирает. |
| `round(..., 2)` | Округление до 2 знаков. Второй аргумент — число знаков после запятой. `round` возвращает число, не строку. |
| `if self.dx == 0` | Вертикальный отрезок. Деление на ноль в вещественной арифметике дало бы `inf` или ошибку, поэтому явно возвращается `None` — «значения нет». |
| `self.dy / self.dx` | Обычное деление. В Python 3 оператор `/` всегда даёт `float`, даже для целых. `4 / 3 = 1.333...`, после `round` получается `1.33`. |
| `DotCalculator((1, 1), (4, 5))` | Два кортежа передаются как `dot1` и `dot2`. |
| `{segment.length():.2f}` | В f-строке после двоеточия формат: `.2f` значит «вещественное, ровно 2 знака». Печать `5.00`, хотя число уже округлено. |
| вторая печать | `1.33`. Если бы `slope` вернул `None`, формат `.2f` вызвал бы ошибку. Для демонстрационной пары точек `dx` не ноль, поэтому печать безопасна. |

Почему разности считаются в конструкторе, а не в каждом методе: обе формулы используют одни и те же `dx` и `dy`. Один расчёт, два метода. Это инкапсуляция: снаружи вызывают `segment.length()` и не знают, как хранится геометрия.

Проверка руками для других точек.

- `(0, 0)` и `(0, 5)`: `dx = 0`, `dy = 5`, длина `5.00`, наклон `None`.
- `(0, 0)` и `(2, 0)`: длина `2.00`, наклон `0.00` — горизонтальный отрезок.
- `(2, 3)` и `(2, 3)`: длина `0.00`, наклон `None`, потому что `dx = 0`. Совпадающие точки дают вырожденный отрезок.

## 14. Практическое задание 2. Блэкджек

### Правила блэкджека в этой работе

Играют два участника: человек и компьютерный дилер. Колоды на руках нет ни у кого заранее. Каждый раунд начинается с новой перемешанной колоды. Деньги — фишки. В начале игры у человека 100 фишек. Дилер на фишки не играет: он только набирает карты и сравнивается с игроком. Ставка игрока либо прибавляется к банку, либо списывается, либо остаётся на месте.

Цель раунда одна. Нужно набрать **больше очков, чем дилер**, и при этом **не набрать больше 21**. Сумма больше 21 называется перебором. Перебор — немедленный проигрыш того, у кого он случился. Сумма ровно 21 перебором не является, это лучшая возможная рука.

#### Колода

Колода стандартная, 52 карты, без джокеров.

Четыре масти: черви, бубны, пики, трефы.

В каждой масти 13 достоинств, по одному разу:

- числа от 2 до 10;
- картинки: валет, дама, король;
- туз.

Всего `4 * 13 = 52`. Повторов нет. Перед раздачей колода перемешивается. Карты снимаются с конца колоды по одной. Одна и та же карта дважды за раунд выпасть не может: снятая карта из колоды удаляется. На следующий раунд собирается новая колода, а не добирается остаток старой.

#### Стоимость карт

| Карта | Очки |
|---|---|
| 2, 3, 4, 5, 6, 7, 8, 9, 10 | ровно написанное число, от 2 до 10 |
| валет, дама, король | 10 каждая |
| туз | 1 или 11, по правилу ниже |

Масть на очки не влияет. Червовый король и пиковый король оба стоят 10. Считается только достоинство.

Туз устроен так. Сначала **каждый** туз в руке стоит 1 очко. Если туз решают считать за 11, к уже посчитанной сумме прибавляют не 11, а **10**: единица уже входит в сумму. Два туза поэтому не могут одновременно стоить по 11: это было бы 22, перебор.

Кто выбирает значение туза:

- **Игрок выбирает сам.** На каждый туз в руке программа спрашивает «1» или «11». Вопрос задаётся заново при каждом подсчёте, в том числе по тузам, которые уже лежали в руке.
- **Дилер выбирает автоматически.** Туз поднимается с 1 до 11 только если после прибавления 10 сумма всё ещё не больше 21. Иначе туз остаётся единицей. Если тузов несколько, проверка повторяется для каждого следующего: второй туз поднимется, только если и после него сумма не превысит 21.

Примеры подсчёта:

- король и 7: `10 + 7 = 17`;
- туз и 6 у дилера: сначала `1 + 6 = 7`, затем `7 + 10 = 17 <= 21`, туз становится 11, итог 17;
- туз и туз у дилера: сначала 2, первый туз поднимается до 12, второй подъём дал бы 22 и не делается, итог 12;
- валет, дама, туз: картинки дают 20, туз остаётся 1, итог 21, а не 31;
- 9, 8 и 5: `9 + 8 + 5 = 22`, это перебор.

#### Ставка

Перед картами игрок видит текущее число фишек и вводит ставку.

Ставка принимается только если выполнены все условия сразу:

- это целое число, записанное цифрами, без минуса и без дробной точки;
- оно не меньше 1;
- оно не больше текущего числа фишек.

Пустой ввод, буквы, ноль, отрицательное число и ставка больше банка отвергаются. Вопрос повторяется, пока не будет годного числа. Поставить больше, чем есть, нельзя. Нулевая ставка не начинается.

#### Раздача

После принятой ставки каждому выдаётся по **две** карты. Порядок такой: сначала две карты игрока, затем две карты дилера. Все четыре карты разные.

Игрок видит:

- обе свои карты и их сумму;
- **только одну** карту дилера, первую в его руке.

Вторая карта дилера закрыта до конца хода игрока.

#### Ход игрока

Игрок ходит первым. Пока ход не кончился, ему показывают карты и очки и предлагают выбор:

- «взять» — снять из колоды ещё одну карту и добавить её в руку;
- «стоп» — закончить набор и оставить текущую сумму.

После каждой новой карты вопрос задаётся снова. Ход прекращается сам, без вопроса, в двух случаях:

- сумма стала **равна 21** — больше карт брать незачем, это потолок;
- сумма стала **больше 21** — перебор, дальнейшие карты положение не спасают.

Если игрок остановился на сумме от 1 до 21 включительно, перебора нет, и ход переходит дилеру. Если сумма больше 21, раунд для игрока уже проигран: ставка списывается сразу, дилер карты не открывает и не добирает.

#### Ход дилера

Дилер не выбирает «взять» или «стоп». У него жесткое правило.

Он открывает обе свои карты и добирает новые, **пока сумма строго меньше 17**. Как только сумма стала 17, 18, 19, 20 или 21, он останавливается. Если при доборе сумма стала больше 21, он тоже останавливается: это его перебор.

Примеры:

- у дилера 10 и 6, сумма 16, 16 < 17, он берёт ещё карту;
- после этой карты сумма стала 20, 20 не меньше 17, он стоит;
- у дилера сразу 10 и 9, сумма 19, он не берёт ничего;
- у дилера туз и 6, автоматический туз даёт 17, он стоит, потому что правило смотрит уже на итог с тузом за 11.

Дилер не подглядывает в карты игрока и не старается их обогнать. Он всегда играет до 17, даже если игроку хватило бы меньшего.

#### Кто выиграл

Сравнение делается только если игрок не перебрал. Ставка к этому моменту ещё не списана и не выплачена: фишки меняются один раз, по итогу.

| Ситуация | Что происходит с фишками |
|---|---|
| У игрока больше 21 | игрок проиграл, ставка списывается, дилер не ходит |
| У дилера больше 21, у игрока 21 или меньше | игрок выиграл, ставка прибавляется |
| Оба не больше 21, у игрока больше, чем у дилера | игрок выиграл, ставка прибавляется |
| Оба не больше 21, у дилера больше, чем у игрока | игрок проиграл, ставка списывается |
| Суммы равны и обе не больше 21 | ничья, ставка возвращается, фишки не меняются |

Выигрыш равен самой ставке, не удвоенной сверх неё отдельно от возврата: при победе к банку прибавляется размер ставки, при поражении тот же размер вычитается. До раунда ставка только названа, с банка она заранее не снимается. Поэтому «прибавить ставку» и значит получить чистый выигрыш в одну ставку, а «вычесть» — потерять её.

Ровно 21 ничем не отличается от любой другой суммы не больше 21, кроме того, что игрок на 21 обязан остановиться. Отдельной премии за две первые карты (классический blackjack 3:2) в этой версии нет. Равные 21 и 21 — ничья, а не победа игрока.

#### Следующий раунд

После итога печатается новый баланс. Игра продолжается, только если фишки ещё есть и игрок ответил «да» на вопрос «сыграть ещё?».

Игра заканчивается, если:

- фишек стало 0 — вопрос уже не задаётся;
- игрок ответил «нет».

Ответы «да» и «нет» нечувствительны к регистру и к пробелам по краям. Другой текст вопрос повторяет.

Новый раунд — это новая ставка, новая колода и новые руки. Старые карты в руке не остаются.

#### Чего в этой версии нет

Чтобы на защите не приписать программе правила обычного казино, которых в коде нет:

- нет раздельной колоды на несколько колод и нет шуза;
- нет удвоения ставки, сплита пары и сдачи;
- нет страховки против туза дилера;
- дилер не стоит на «мягких 17» по отдельному правилу казино: он просто смотрит на уже посчитанную сумму и берёт карту, пока она меньше 17;
- закрытая карта дилера не участвует в решениях игрока, игрок её не видит;
- игрок не получает полторы ставки за блэкджек с двух карт.

Всё перечисленное выше — полное правило именно этой лабораторной. Код `Deck`, `Hand`, `choose` и `play` делает только его.

### Класс `Deck`

```python
import random

class Deck:
    def __init__(self):
        suits = ["черви", "бубны", "пики", "трефы"]
        ranks = [str(n) for n in range(2, 11)] + ["валет", "дама", "король", "туз"]
        self.cards = [(rank, suit) for suit in suits for rank in ranks]
        random.shuffle(self.cards)

    def draw(self):
        return self.cards.pop()
```

| Строка | Разбор |
|---|---|
| `import random` | Модуль псевдослучайных чисел. |
| `suits = [...]` | Четыре масти, локальная переменная конструктора. В объект она не сохраняется: после создания колоды список мастей не нужен. |
| `[str(n) for n in range(2, 11)]` | Списковое включение. `range(2, 11)` даёт числа 2…10. `str(n)` превращает число в строку: `"2"`, …, `"10"`. Строки нужны, чтобы достоинство всегда было текстом, как `"валет"`. |
| `+ ["валет", "дама", "король", "туз"]` | Конкатенация списков. Итог — 13 достоинств. |
| `[(rank, suit) for suit in suits for rank in ranks]` | Вложенный перебор. **Левый** цикл внешний: сначала все карты червей от 2 до туза, потом бубны и так далее. Каждый элемент — кортеж `(достоинство, масть)`. Кортеж выбран, потому что карта после создания не меняется. Всего `4 * 13 = 52` пары, повторов нет. |
| `random.shuffle(self.cards)` | Перемешивание **на месте**. Функция возвращает `None`, поэтому результат не присваивают. После вызова порядок карт случаен. |
| `self.cards.pop()` | Снимает и возвращает последний элемент. Удаление с конца списка выполняется за постоянное время. Колода укорачивается. Повторный `draw` на пустой колоде даст `IndexError`; в этой игре столько карт не берут. |

### Класс `Hand`

```python
class Hand:
    def __init__(self, deck):
        self.cards = [deck.draw(), deck.draw()]

    def show(self):
        return ", ".join(rank + " (" + suit + ")" for rank, suit in self.cards)

    def score(self, player=False):
        total = 0
        aces = 0
        for rank, suit in self.cards:
            if rank == "туз":
                aces += 1
            elif rank.isdigit():
                total += int(rank)
            else:
                total += 10

        total += aces
        for _ in range(aces):
            if player:
                if choose("Сколько очков дать тузу?", ["1", "11"]) == "11":
                    total += 10
            elif total + 10 <= 21:
                total += 10
        return total
```

| Часть | Смысл |
|---|---|
| `Hand(deck)` | Рука получает колоду и сразу берёт две карты. `deck.draw()` вызывается дважды, результаты собираются в список. |
| `show` | Генераторное выражение проходит по картам. `rank + " (" + suit + ")"` склеивает строки плюсом: `"туз (пики)"`. `", ".join(...)` соединяет куски через запятую с пробелом. |
| `score(self, player=False)` | Параметр по умолчанию `False` означает «это дилер, тузы выбирать автоматически». Для человека вызывают `score(player=True)`. |
| `total = 0`, `aces = 0` | Накопитель очков и счётчик тузов. Туз нельзя сразу прибавить как 1 или 11: решение зависит от остальных карт и от того, кто ходит. |
| `for rank, suit in self.cards` | Распаковка кортежа карты. Масть `suit` в подсчёте не используется, но распаковать её нужно, потому что элемент — пара. |
| `rank == "туз"` | Сравнение строк. Туз только считается. |
| `elif` | Проверяется, только если карта не туз. |
| `rank.isdigit()` | Метод строки: `True`, если все символы — цифры. Подходит `"2"`…`"10"`. У `"10"` два символа, и оба цифры, поэтому метод истинен. |
| `int(rank)` | Строка `"10"` становится числом `10`. |
| `else: total += 10` | Сюда попадают валет, дама, король. |
| `total += aces` | Каждый туз пока стоит 1. |
| `for _ in range(aces)` | Цикл по числу тузов. Имя `_` значит «переменная не используется», важен только повтор. |
| ветка `player` | Каждый туз спрашивается отдельно. Ответ `"11"` добавляет 10, потому что 1 уже учтена. Ответ `"1"` ничего не добавляет. |
| ветка дилера | `elif` относится к `if player`. Если это не игрок и `total + 10 <= 21`, туз поднимается до 11. Условие проверяется заново на каждом тузе, поэтому второй туз не поднимется, если первый уже сделал сумму высокой. Пример: туз и шестёрка дают `7`, `7 + 10 = 17 <= 21`, туз становится 11, сумма 17. Два туза: сначала 2, первый поднимается до 12, второй подъём дал бы 22 и не выполняется. |
| `return total` | Итоговое целое число очков. |

Важная деталь защиты: `score(player=True)` спрашивает тузы **при каждом вызове**, в том числе за тузы, которые уже лежали в руке. Так сделано, потому что отдельного хранилища «уже выбранных значений туза» нет. Игрок подтверждает выбор заново после каждой новой карты.

### Ввод и партия

```python
def choose(prompt, options):
    while True:
        answer = input(prompt + " (" + "/".join(options) + ") ").strip().lower()
        if answer in options:
            return answer

def play():
    chips = 100
    while chips > 0:
        print("Ваши фишки:", chips)
        while True:
            bet_text = input("Введите ставку: ").strip()
            if bet_text.isdecimal() and 1 <= int(bet_text) <= chips:
                bet = int(bet_text)
                break
            print("Введите целое число от 1 до", chips)

        deck = Deck()
        player = Hand(deck)
        dealer = Hand(deck)
        print("Открытая карта дилера:", *dealer.cards[0])
        while True:
            print("Ваши карты:", player.show())
            points = player.score(player=True)
            print("Ваши очки:", points)
            if points >= 21 or choose("Ваш ход?", ["взять", "стоп"]) == "стоп":
                break
            player.cards.append(deck.draw())

        if points > 21:
            chips -= bet
            print("Перебор. Ставка проиграна.")
        else:
            while dealer.score() < 17:
                dealer.cards.append(deck.draw())
            other = dealer.score()
            print("Карты дилера:", dealer.show(), "Очки:", other)
            if other > 21 or points > other:
                chips += bet
                print("Вы выиграли ставку.")
            elif points < other:
                chips -= bet
                print("Дилер выиграл ставку.")
            else:
                print("Ничья. Ставка возвращается.")
        print("Баланс после раунда:", chips)
        if chips == 0 or choose("Сыграть ещё?", ["да", "нет"]) == "нет":
            break

# play()
```

| Часть | Смысл |
|---|---|
| `def choose(prompt, options)` | Общая функция вопроса. `prompt` — текст, `options` — список допустимых строк. |
| `while True` | Бесконечный цикл, пока ответ не подойдёт. Выход только через `return` или `break`. |
| `input(...)` | Читает строку с клавиатуры. Пока пользователь не нажмёт Enter, программа ждёт. |
| `"/".join(options)` | Из `["взять", "стоп"]` получается текст `взять/стоп`. |
| `.strip()` | Убирает пробелы по краям. |
| `.lower()` | Приводит к нижнему регистру, чтобы `"Да"` совпало с `"да"`. |
| `if answer in options` | Проверка членства в списке. Пустой ввод и мусор игнорируются, вопрос повторяется. |
| `chips = 100` | Стартовый банк. Локальная переменная функции `play`. |
| `while chips > 0` | Внешний цикл партий. При нуле игра больше не начинается. |
| `bet_text.isdecimal()` | `True` только для непустой строки из десятичных цифр. Не пройдут `"-"`, `"3.5"`, `" 5"` уже после `strip` станет `"5"` и пройдёт, пустая строка не пройдёт. |
| `1 <= int(bet_text) <= chips` | Двойное сравнение: число одновременно не меньше 1 и не больше банка. Так отсекаются `0` и ставка больше фишек. |
| `break` внутреннего цикла | Ставка принята, повторный вопрос не нужен. |
| `Deck()` | Новая перемешанная колода на каждый раунд. |
| `Hand(deck)` дважды | Сначала две карты игрока, потом две карты дилера. Все четыре карты разные, потому что `draw` удаляет карту из колоды. |
| `*dealer.cards[0]` | Звёздочка распаковывает кортеж карты в отдельные аргументы `print`. Печатается достоинство и масть через пробел. Вторая карта дилера скрыта. |
| цикл игрока | Показывает руку, считает очки с вопросами про тузы. |
| `points >= 21 or ...` | Оператор `or` вычисляет правую часть только если левая ложна. При 21 и больше вопрос «взять или стоп» **не задаётся**. При сумме меньше 21 вопрос задаётся. Если ответ `"стоп"`, цикл заканчивается. Иначе берётся ещё одна карта через `append`. |
| `if points > 21` | Перебор игрока. Дилер карты не добирает, ставка сразу списывается. Ровно 21 перебором не является. |
| `while dealer.score() < 17` | Правило дилера: добирает, пока строго меньше 17. На 17 и выше останавливается. Вызов без аргументов использует `player=False`. |
| `other = dealer.score()` | Повторный подсчёт уже после добора. Для дилера он детерминирован, второй вызов даёт то же число. |
| `other > 21 or points > other` | Игрок выигрывает, если дилер перебрал **или** у игрока больше очков. Ставка прибавляется. |
| `elif points < other` | Дилер ближе к 21, не перебрав. Ставка списывается. |
| `else` | Равенство. Фишки не меняются, это ничья. |
| `chips == 0 or ... == "нет"` | Конец игры при банкротстве или отказе. При нуле фишек вопрос «сыграть ещё?» не задаётся из-за короткого `or`. |
| `# play()` | Вызов закомментирован. Ячейку можно выполнить, и игра не начнёт бесконечно ждать `input`. Для партии строку раскомментируют или вызовут `play()` в следующей ячейке. |

Где здесь ООП: `Deck` отвечает только за колоду, `Hand` — за карты руки и очки, `play` — за ставки и правила раунда. Полиморфизм в этой задаче не обязателен: игрок и дилер — два объекта одного класса `Hand`, различие задаётся аргументом `player`.

## 15. Тензоры: создание

Тензор — многомерный массив с одним типом элементов. В отличие от списка Python он лежит сплошным блоком памяти, умеет считаться на GPU и запоминать операции для производных.

```python
v = torch.empty(10)
m = torch.empty(2, 3)
x = torch.empty_like(m)
```

`torch.empty` выделяет память и **не заполняет** её. Числа внутри — мусор, пока в тензор не запишут. `empty(10)` — вектор длины 10. `empty(2, 3)` — матрица 2 строки на 3 столбца. `empty_like(m)` создаёт новый тензор той же формы и типа, что `m`, тоже без инициализации. Так делают, когда значения всё равно сразу перезапишутся и тратить время на нули незачем.

```python
x = torch.tensor([[0,1,2], [3,4,6]])
s = torch.tensor(137.)
s = torch.tensor(137, dtype=torch.double)
```

`torch.tensor` копирует данные из списка Python. Внешний список — строки, внутренние — элементы строки. Форма получается `(2, 3)`. Литерал `137.` с точкой — это `float`, поэтому тензор станет вещественным, по умолчанию `float32`. Целое `137` без точки дало бы целочисленный тензор, но именованный аргумент `dtype=torch.double` принудительно выбирает `float64`. Имя `s` во второй строке заново связывается с новым тензором, старый объект остаётся без имени.

```python
import numpy as np
e = torch.from_numpy(np.eye(3))
print(e)
```

`np.eye(3)` — единичная матрица NumPy 3×3: единицы на диагонали, нули вокруг. `torch.from_numpy` делает тензор, который **делит память** с массивом. Изменение элемента тензора меняет массив и наоборот. Если нужна независимая копия, берут `torch.tensor(numpy_array)`.

## 16. Свойства тензора

```python
x = torch.empty(2, 3)
print(f"Число осей: {x.dim()},\\nТип элементов: {x.type()},\\nЧисло элементов: {x.numel()}")
print(f"Форма через метод и атрибут: {x.size()}, {x.shape}")
print("Размеры как кортеж", tuple(x.shape))
print("Размеры после распаковки", *x.shape)
```

| Вызов | Результат для формы `(2, 3)` |
|---|---|
| `x.dim()` | Число осей, ранг. Здесь `2`. |
| `x.type()` | Строка с типом, например `torch.FloatTensor`. |
| `x.numel()` | Число элементов: `2 * 3 = 6`. От *number of elements*. |
| `x.size()` | Метод, возвращает форму как `torch.Size`. |
| `x.shape` | Атрибут с той же формой. На практике читают его. |
| `tuple(x.shape)` | Обычный кортеж `(2, 3)`. |
| `*x.shape` | Распаковка в аргументы `print`, печатается `2 3` через пробел. |

Память одного элемента: `float64` — 8 байт, `float32` — 4, `float16` — 2. Тензор из миллиона чисел в `float32` занимает около 4 МБ, в `float64` — около 8 МБ. Для больших моделей тип выбирают ещё и из-за скорости GPU: `float32` и `float16` считаются быстрее `float64`. Обучение нейросетей почти всегда идёт в `float32` или ниже, не в `float64`.

```python
s = torch.tensor(137)
print(s, s.dim(), s.item(), s.type())

m = torch.tensor([[137]])
print(m, m.dim(), m.item(), m[0, 0])
```

Скаляр `torch.tensor(137)` имеет `dim() == 0`: осей нет, это одно число, упакованное в тензор. `item()` достаёт из тензора **ровно одного** элемента обычное число Python. Если элементов больше одного, `item()` вызовет ошибку.

`torch.tensor([[137]])` — матрица формы `(1, 1)`, осей уже две. `item()` снова работает, потому что элемент один. `m[0, 0]` — индексация сразу по двум осям: строка 0, столбец 0. Запятая внутри скобок отделяет индексы осей.

## 17. Инициализация

```python
y = torch.zeros(2, 3)
x = torch.zeros_like(y)

x = torch.ones(2, 3)
x = torch.eye(3)
x = torch.eye(2, 3)

x = torch.linspace(0, 2, 5)

x = torch.rand(2, 3)
x = torch.randn(2, 3)

x = torch.arange(4)
x = torch.arange(2, 14, 3)

x = torch.randperm(10)
```

| Вызов | Что получается |
|---|---|
| `zeros(2, 3)` | Матрица нулей. |
| `zeros_like(y)` | Нули той же формы и типа, что `y`. |
| `ones(2, 3)` | Матрица единиц. |
| `eye(3)` | Единичная матрица 3×3. |
| `eye(2, 3)` | Прямоугольная матрица 2×3 с единицами на главной диагонали и нулями в остальных местах. |
| `linspace(0, 2, 5)` | 5 точек от 0 до 2 **включительно**, с равным шагом: `0, 0.5, 1, 1.5, 2`. |
| `rand(2, 3)` | Равномерное распределение на полуинтервале `[0, 1)`. |
| `randn(2, 3)` | Стандартное нормальное распределение, среднее 0, дисперсия 1. Буква `n` в имени — normal. |
| `arange(4)` | `0, 1, 2, 3`. Конец не входит. |
| `arange(2, 14, 3)` | Старт 2, шаг 3, пока меньше 14: `2, 5, 8, 11`. |
| `randperm(10)` | Случайная перестановка чисел `0 … 9`, каждое один раз. |

В этой ячейке имя `x` много раз перезаписывается. В памяти ноутбука после выполнения остаётся только последний тензор, перестановка. Промежуточные нужны как демонстрация API, а не как одновременно живущие данные.

## 18. Память: представление и операция на месте

В PyTorch есть два вида операций.

- Обычная, например `exp`, создаёт **новый** тензор.
- Операция с подчёркиванием на конце, например `exp_`, пишет результат **в тот же** тензор.

```python
x = torch.ones(1)
y = x.exp()
print(x)
y[0] = 2
print(x.item())

x = torch.ones(1)
y = x.exp_()
print(x)
y[0] = 2
print(x.item())
```

Первый блок. `x` — единица. `x.exp()` считает `e^1` и кладёт это в новый тензор `y`. Сам `x` остаётся единицей. Затем `y[0] = 2` меняет только `y`. Печать `x.item()` даёт `1`.

Второй блок. `exp_` записывает экспоненту прямо в `x` и возвращает тот же объект. Поэтому `y` и `x` — одна память, `x is y` было бы истинно. Запись `y[0] = 2` видна и через `x`: печать даёт `2`.

```python
x = torch.empty(2, 3).fill_(-1)
x.zero_()
```

`fill_(-1)` заполняет уже выделенный тензор числом −1 и возвращает его же, поэтому цепочку можно продолжать. `zero_()` затирает все элементы нулями. Подчёркивание снова значит «изменить себя».

```python
y = x
print(x is y)

y = x.clone()
print(x is y)

x = torch.empty(10)
y = torch.empty_like(x)
y.copy_(x)

y = torch.empty_like(x).copy_(x)
```

| Строка | Смысл |
|---|---|
| `y = x` | Новое имя на тот же объект. Данные не копируются. |
| `x is y` | Проверка идентичности объектов, не равенства чисел. Здесь `True`. |
| `x.clone()` | Настоящая копия значений. `x is y` становится `False`. Дальнейшая запись в `y` не трогает `x`. |
| `empty_like` + `copy_` | Память под `y` выделяется заранее, затем в неё копируются байты `x`. Удобно, когда буфер уже есть и заводить третий тензор не нужно. |
| цепочка `.copy_(x)` | `copy_` возвращает сам тензор, поэтому результат цепочки можно сразу присвоить `y`. |

Операторы `is` и `==` различаются. `==` для тензоров сравнивает элементы и возвращает тензор из `True`/`False`. `is` отвечает на вопрос «это один и тот же объект в памяти?».

## 19. Индексация и арифметика

```python
x1, x2 = torch.ones(2, 3), torch.ones(2, 3)

print(x1)
x1[0] = 2
print(x1)

print(x2)
x2[:, 1] = 3
print(x2)

y = x1 + x2
print(y)
```

`x1, x2 = ...` — распаковка двух новых матриц единиц.

`x1[0] = 2` выбирает первую строку целиком и записывает в каждый её элемент 2. Число `2` растягивается на форму строки. Это называется broadcasting: маленькая форма дополняется, пока не совпадёт с большой, если размеры равны или равны 1.

`x2[:, 1] = 3`. Двоеточие без границ значит «вся ось». Первая ось — все строки, вторая ось — столбец с индексом 1, то есть второй столбец. В него записываются тройки.

`x1 + x2` — поэлементное сложение, новый тензор. Для первой строки `2+1`, `2+3`, `2+1`. Для второй `1+1`, `1+3`, `1+1`.

```python
x, y = torch.ones(2, 3), torch.ones(2, 3)

x += y
print(x)
x.add_(y)
print(x)
x.add_(y, alpha=2.0)
print(x)
```

`x += y` прибавляет `y` к `x` на месте. После этого все элементы `x` равны 2.

`x.add_(y)` делает то же самое методом: каждый элемент увеличивается ещё на 1, становится 3.

`alpha=2.0` означает «прибавить `alpha * y`». Прибавляется `2 * 1 = 2`, элементы становятся 5. Именованный аргумент `alpha` — множитель второго слагаемого, не скорость обучения.

```python
v = torch.tensor([1., 2., 3.])
u = torch.tensor([-1., 3., 4.])

v.dot(u)

x.mm(y.T)
x.mv(v)

x = torch.rand([2, 3, 4])
y = torch.rand([2, 4, 5])
x.bmm(y)
x.matmul(y)
```

| Операция | Формула и формы |
|---|---|
| `v.dot(u)` | Скалярное произведение: `1*(-1) + 2*3 + 3*4 = 17`. Оба аргумента — векторы одной длины. |
| `y.T` | Транспонирование матрицы: строки становятся столбцами. |
| `x.mm(y.T)` | Матричное умножение строго двумерных тензоров. Внутренние размеры должны совпасть. |
| `x.mv(v)` | Матрица на вектор. Результат — вектор. |
| `torch.rand([2, 3, 4])` | Пакет из 2 матриц `3×4`. Список в аргументе задаёт форму так же, как отдельные числа. |
| `bmm` | Batch matrix multiply. Умножает соответствующие матрицы пакета, пакетная ось не смешивается. Формы `(2, 3, 4)` и `(2, 4, 5)` дают `(2, 3, 5)`. |
| `matmul` | Более общий оператор матричного умножения, для этих форм совпадает с `bmm`. Записывается ещё как оператор `@`. |

В этой ячейке `x.mm` и `x.mv` используют `x` и `y`, оставшиеся от предыдущей ячейки, где они были матрицами `2×3`. Порядок запуска ячеек важен: если запустить только эту ячейку, имён `x` и `y` нужной формы может не быть.

## 20. Форма, транспонирование, шаги памяти

```python
torch.arange(12).view(3, 4)
torch.arange(12).reshape(2, 2, 3)
```

`arange(12)` — числа `0 … 11` в одну строку памяти. `view(3, 4)` смотрит на те же 12 чисел как на матрицу 3×4. `reshape(2, 2, 3)` смотрит на них как на тензор из двух матриц 2×3. Число элементов обязано сохраниться: `3*4 = 12`, `2*2*3 = 12`. Иначе будет ошибка.

Функция `show_tensor(shape)` в ноутбуке только рисует схему формы через HTML: для одной оси — ряд клеток, для двух — таблицу, для трёх — не больше трёх срезов. На вычисления она не влияет. Индекс в клетке считается как линейный номер элемента в порядке «строка за строкой».

```python
x = torch.arange(6).view(2, 3)
print(x)
z = x.t()
print(z)
z = x.t_()
```

Исходная матрица:

```text
0 1 2
3 4 5
```

`t()` возвращает транспонированное **представление** формы `(3, 2)`:

```text
0 3
1 4
2 5
```

Память обычно не копируется, меняются форма и шаги. `t_()` транспонирует сам тензор `x` и возвращает его. После этого `x` уже имеет форму `(3, 2)`.

```python
x = torch.arange(12).view(2, 2, 3)
x = x.transpose(1, 2)
```

`transpose(1, 2)` меняет местами оси с номерами 1 и 2. Было `(2, 2, 3)`, стало `(2, 3, 2)`. Ось 0 не трогается. Для матрицы `transpose(0, 1)` совпадает с обычным транспонированием.

```python
x = torch.tensor([
    [0, 1, 2],
    [3, 4, 5]
])
print(x.t())
print(x.view(3, 2))
```

Это разные операции, хотя обе дают форму `(3, 2)`.

`t()` переставляет элементы:

```text
0 3
1 4
2 5
```

`view(3, 2)` не переставляет числа, а только заново группирует их в порядке хранения:

```text
0 1
2 3
4 5
```

Шаг (stride) — на сколько элементов нужно сдвинуться в памяти, чтобы увеличить индекс данной оси на 1.

Для матрицы `2×3`, лежащей подряд по строкам, шаги равны `(3, 1)`: следующая строка начинается на 3 элемента дальше, следующий столбец — на 1 элемент. После транспонирования шаги меняются местами на `(1, 3)`, а сами числа в памяти остаются на местах.

Непрерывное расположение (`contiguous`) значит, что элементы идут в памяти в том же порядке, в каком их обходит форма. Транспонированный тензор часто непрерывен **не** в новом порядке. Метод `.contiguous()` при необходимости копирует данные так, чтобы шаги снова были плотными. Метод `.view()` требует совместимых шагов и тогда память не копирует. Если шаги не подходят, `view` падает с ошибкой. Метод `.reshape()` в совместимом случае тоже возвращает представление, а если так нельзя — молча копирует и уже потом меняет форму.

Картинка `show_transpose()` в ноутбуке рисует ту же пару матриц `2×3` и `3×2` средствами HTML. Это иллюстрация, не часть расчёта.

## 21. Вычисления на GPU

```python
import time

cpu = torch.device("cpu")
gpu = torch.device("cuda" if torch.cuda.is_available() else "cpu")
print("Доступное устройство:", gpu)
```

`torch.device` — объект «где лежат данные». Тернарное выражение `a if условие else b` выбирает `"cuda"`, если GPU доступен, иначе запасной `"cpu"`. Тогда дальнейший код не падает на машине без видеокарты.

```python
def measure(device, transfer=False):
    start = time.perf_counter()
    source = cpu if transfer else device
    a = torch.eye(1024, device=source).to(device)
    b = torch.eye(1024, device=source).to(device)
    result = a.mm(b)
    if transfer:
        result = result.cpu()
    if device.type == "cuda":
        torch.cuda.synchronize()
    print(f"Время: {time.perf_counter() - start:.4f} с")

measure(cpu)
```

| Часть | Смысл |
|---|---|
| `transfer=False` | По умолчанию матрицы сразу создаются на целевом устройстве, перенос не измеряется отдельно. |
| `time.perf_counter()` | Монотонный счётчик секунд с дробной частью, подходит для коротких замеров. |
| `source = ...` | Если `transfer` истинно, источник — CPU, даже когда цель — GPU. Иначе источник совпадает с целью. |
| `torch.eye(1024, device=source)` | Единичная матрица 1024×1024 сразу в нужной памяти. Размер выбран так, чтобы пример закончился на обычном ноутбуке. Элементов около миллиона, умножение — порядка `1024³` арифметических операций. |
| `.to(device)` | Копия на целевое устройство. Если источник и цель совпали, лишнего переноса нет. |
| `a.mm(b)` | Матричное произведение. На GPU вызов только **ставит работу в очередь**, функция может вернуться раньше, чем умножение закончится. |
| `result.cpu()` | Возврат результата в оперативную память. Это тоже асинхронная относительно GPU операция, пока нет синхронизации. |
| `device.type == "cuda"` | У объекта устройства есть строковое поле `type`. |
| `torch.cuda.synchronize()` | Ждёт, пока GPU доделает все поставленные ядра. Без этого таймер остановится слишком рано и время GPU будет занижено. |
| `:.4f` | Печать секунд с четырьмя знаками после запятой. |
| `measure(cpu)` | Контрольный замер на процессоре. |

```python
if gpu.type == "cuda":
    measure(gpu)
else:
    print("CUDA недоступна.")
```

Вторая ветка создаёт обе матрицы сразу на GPU и умножает их там. Перенос большого массива в замер не входит.

```python
if gpu.type == "cuda":
    measure(gpu, transfer=True)
```

Третий замер включает дорогу туда и обратно: создать на CPU, скопировать на GPU, умножить, скопировать результат назад. На маленьких матрицах перенос может съесть всю выгоду GPU. Вывод для защиты: GPU выгоден, когда вычислений много, а данные уже лежат на устройстве. Гонять каждый мелкий тензор через шину PCIe ради одной операции часто медленнее CPU.

```python
def show_memory():
    print("Память тензоров, байт:", torch.cuda.memory_allocated())
    print("Зарезервировано, байт:", torch.cuda.memory_reserved())

if gpu.type == "cuda":
    print("До очистки кеша")
    show_memory()
    torch.cuda.empty_cache()
    print("После очистки кеша")
    show_memory()
```

`memory_allocated` — байты, которые сейчас занимают живые тензоры. `memory_reserved` — сколько видеопамяти процесс PyTorch зарезервировал у драйвера, включая свободный кеш под следующие выделения. `empty_cache()` отдаёт драйверу неиспользуемый кеш. Живые тензоры она не удаляет. Если на них ещё есть ссылки Python, `memory_allocated` не уменьшится. Уменьшается обычно `memory_reserved`.

Загрузка GPU — доля времени, когда чип занят ядрами. Расход видеопамяти — объём данных. Это разные величины: карта может быть почти пустой по памяти и при этом загружена на 100 процентов, и наоборот.

### Загрузчики

```python
BATCH = 64

train_dataset = TensorDataset(train_X, train_y)
val_dataset = TensorDataset(val_X, val_y)

train_loader = DataLoader(train_dataset, batch_size=BATCH, shuffle=True)
val_loader = DataLoader(val_dataset, batch_size=BATCH)

next(iter(train_loader))
```

`TensorDataset` сам реализует `__len__` и `__getitem__`: по индексу возвращает срез каждого переданного тензора. Пара — признаки и метка одной строки.

`shuffle=True` только у обучения. Проверочный набор перемешивать не нужно: по нему не обновляют веса, и порядок на метрику среднего не влияет.

`iter(train_loader)` создаёт итератор по эпохе, `next` берёт первый пакет. Это проверка, что загрузчик жив. Пакет — кортеж из тензора признаков формы `(64, 2)` и тензора меток формы `(64,)`. Последний пакет эпохи может быть короче, если 3750 не делится на 64: `3750 = 58 * 64 + 38`, то есть 58 полных пакетов и один пакет длины 38.

Имя `val_loader` в дальнейшем коде напрямую не используется: проверка считается одним проходом по всему `val_X`. Загрузчик проверки оставлен как заготовка того же интерфейса.

### Модель, обучение, доля верных ответов

Линейная модель для одной точки `(x1, x2)`:

```text
прогноз = w1 * x1 + w2 * x2 + b
```

В матричном виде для пакета `X` формы `(N, 2)`:

```text
прогноз = X W^T + b
```

У `nn.Linear(2, 1)` матрица `W` имеет форму `(1, 2)`, смещение `b` — форму `(1)`. Обучаемых чисел три.

Функция потерь — среднеквадратичная ошибка. Если прогнозы `p` и метки `y` длины `N`:

```text
MSE = (1/N) * Σ (p_i - y_i)²
```

Метка 0 или 1, прогноз — вещественное число. Ошибка большая, когда прогноз далеко от своей метки. Минимизировать MSE по весам — и есть постановка линейной регрессии, хотя метки здесь классовые. Порог 0.5 потом превращает число в класс.

Градиентный спуск. На каждом пакете считаются частные производные потерь по каждому весу. Шаг SGD:

```text
w := w - lr * ∂L/∂w
```

`lr = 0.03`. Минус нужен, потому что градиент показывает направление роста ошибки, а ошибку надо уменьшать.

```python
linear = nn.Linear(2, 1).to(DEVICE)

def train(model, epochs):
    loss_fn = nn.MSELoss()
    optimizer = torch.optim.SGD(model.parameters(), lr=0.03)
    model.train()
    for epoch in range(epochs):
        for features, labels in train_loader:
            features = features.to(DEVICE)
            labels = labels.to(DEVICE)
            optimizer.zero_grad()
            predictions = model(features).squeeze(1)
            loss = loss_fn(predictions, labels)
            loss.backward()
            optimizer.step()

def accuracy(model):
    model.eval()
    with torch.no_grad():
        predictions = model(val_X.to(DEVICE)).squeeze(1).cpu()
        predicted = (predictions >= 0.5).long()
        return (predicted == val_y).float().mean().item()

train(linear, epochs=30)
linear_accuracy = accuracy(linear)
print(f"Доля верных ответов линейной модели: {linear_accuracy:.1%}")
```

| Строка | Зачем она стоит именно здесь |
|---|---|
| `nn.Linear(2, 1)` | Два входа, один выход. Веса инициализирует сам PyTorch. |
| `.to(DEVICE)` | И параметры слоя переезжают на то же устройство, что данные. Сложение тензоров с CPU и CUDA в одной операции запрещено. |
| `nn.MSELoss()` | Модуль функции потерь. По умолчанию reduction `'mean'`: одно число, среднее по пакету. |
| `SGD(model.parameters(), lr=0.03)` | Оптимизатор получает итератор обучаемых тензоров. `parameters()` отдаёт вес и смещение. `lr` — шаг. |
| `model.train()` | Режим обучения. У этой модели нет Dropout и BatchNorm, поэтому флаг поведение слоёв не меняет, но его ставят по правилу: перед обучением `train`, перед проверкой `eval`. |
| `for epoch in range(epochs)` | 30 полных проходов по обучающей выборке. |
| `for features, labels in train_loader` | Один шаг — один пакет. Из-за `shuffle` порядок пакетов каждую эпоху новый. |
| `.to(DEVICE)` внутри цикла | Пакет по умолчанию на CPU, потому что тензоры выборки туда положили при создании. На GPU едет только текущий пакет, а не обязательно весь датасет заранее. |
| `zero_grad()` | Обнуляет накопленные градиенты. В PyTorch градиенты **суммируются** при каждом `backward`, пока их не стереть. Без обнуления шаг пошёл бы по сумме градиентов всех прошлых пакетов. |
| `model(features)` | Прямой проход. Выход слоя имеет форму `(B, 1)`. |
| `.squeeze(1)` | Убирает ось номер 1, если её длина равна 1. Форма становится `(B,)`, как у меток. Без этого MSE сравнивала бы `(B, 1)` и `(B,)` и из-за broadcasting могла бы раздуть ошибку в матрицу `(B, B)`. |
| `loss_fn(...)` | Скалярный тензор потерь. У него включён граф вычислений, потому что входы зависят от весов с `requires_grad=True`. |
| `loss.backward()` | Автодифференцирование. PyTorch проходит граф от скаляра потерь к весам и записывает частные производные в поле `.grad` каждого параметра. |
| `optimizer.step()` | Применяет формулу SGD к весу и смещению. |
| `model.eval()` | Режим проверки. |
| `torch.no_grad()` | Внутри блока операции не записываются в граф. Память не тратится на производные, случайно вызвать `backward` по этому проходу нельзя. Для доли верных ответов граф не нужен. |
| `.cpu()` | Метки `val_y` лежат на CPU. Сравнение должно идти на одном устройстве, поэтому прогнозы возвращают с GPU. |
| `>= 0.5` | Поэлементное сравнение. Получается булев тензор. Порог посредине между метками 0 и 1: прогноз ближе к единице считается классом 1. |
| `.long()` | `True/False` превращаются в целые `1/0`. |
| `predicted == val_y` | Поэлементное равенство. |
| `.float().mean()` | `True` становится 1.0, `False` — 0.0, среднее — доля совпадений. |
| `.item()` | Достаёт эту долю как число Python. |
| `:.1%` | Формат процента с одним знаком. Множитель 100 и знак `%` добавляет сам формат. |
| `epochs=30` | Именованная передача. Число небольшое: линейная модель быстро выходит на плато, дальше прямую границу не улучшить числом эпох. |

Почему линейная модель ошибается на лунах. Её граница — прямая: множество точек, где `w1*x1 + w2*x2 + b = 0.5`. Две луны линейно неразделимы. Любая прямая оставляет куски чужого класса по обе стороны. Доля верных ответов оказывается заметно ниже, чем у сети со скрытыми слоями, и круги ошибок на графике ложатся дугами, которые прямая не может обогнуть.

### График ошибок

```python
def show_errors(model):
    with torch.no_grad():
        predicted = model(val_X.to(DEVICE)).squeeze(1).cpu() >= 0.5
    errors = predicted != val_y
    plt.scatter(val_X[:, 0], val_X[:, 1], c=val_y, cmap="coolwarm", s=10)
    plt.scatter(val_X[errors, 0], val_X[errors, 1], facecolors="none",
                edgecolors="black", s=35, label="Ошибки")
    plt.xlabel("Первый признак")
    plt.ylabel("Второй признак")
    plt.legend()
    plt.show()

show_errors(linear)
```

| Часть | Смысл |
|---|---|
| `predicted = ... >= 0.5` | Булева маска верных классов на проверке. |
| `errors = predicted != val_y` | Маска ошибок той же длины, что проверочная выборка. `!=` поэлементный. |
| первый `scatter` | Все проверочные точки, цвет — истинный класс, размер маркера `s=10`. |
| `val_X[errors, 0]` | Логическая индексация: остаются только строки, где маска `True`, и столбец 0. Так берутся координаты ошибочных точек. |
| `facecolors="none"` | Маркер без заливки. |
| `edgecolors="black"` | Чёрная обводка. Ошибка видна кольцом поверх цветной точки. |
| `label="Ошибки"` | Текст для легенды. Легенда появляется только после `plt.legend()`. |
| `xlabel`, `ylabel` | Подписи осей. |

## 23. Практическое задание 4. Полносвязная сеть

Условие: обучить полносвязную сеть на тех же данных. Функция `train`, функция `accuracy`, загрузчик и число эпох те же. Меняется только модель.

```python
network = nn.Sequential(
    nn.Linear(2, 16),
    nn.ReLU(),
    nn.Linear(16, 16),
    nn.ReLU(),
    nn.Linear(16, 1),
).to(DEVICE)

train(network, epochs=30)
network_accuracy = accuracy(network)
print(f"Линейная модель: {linear_accuracy:.1%}")
print(f"Полносвязная сеть: {network_accuracy:.1%}")
show_errors(network)
```

`nn.Sequential` — контейнер. При вызове `network(x)` модули применяются по очереди, выход предыдущего становится входом следующего. Отдельный класс с `forward` здесь не нужен, потому что ветвлений нет.

Слои по порядку.

| № | Модуль | Форма входа → выхода | Что делает |
|---|---|---|---|
| 1 | `Linear(2, 16)` | `(B, 2)` → `(B, 16)` | 16 линейных комбинаций двух признаков. Весов `2*16 = 32`, смещений 16. |
| 2 | `ReLU()` | `(B, 16)` → `(B, 16)` | `max(0, z)` поэлементно. Обучаемых параметров нет. |
| 3 | `Linear(16, 16)` | `(B, 16)` → `(B, 16)` | Второе линейное преобразование. Весов `16*16 = 256`, смещений 16. |
| 4 | `ReLU()` | та же форма | Вторая нелинейность. |
| 5 | `Linear(16, 1)` | `(B, 16)` → `(B, 1)` | Одно число на точку, как у линейной модели. Весов 16, смещение 1. |

Всего обучаемых параметров: `(32+16) + (256+16) + (16+1) = 337`. У линейной модели их было 3. Сеть богаче, но 337 чисел на 3750 точек — небольшая модель, переобучение на этих данных не главная проблема.

Почему появляются кривые границы. Один линейный слой режет пространство гиперплоскостью. ReLU складывает пространство по нулю: отрицательная полуось осирается. Несколько таких кусков, снова смешанных линейным слоем, собираются в ломаную границу. Двух скрытых слоёв по 16 нейронов хватает, чтобы обогнуть месяц. Поэтому доля верных ответов сети выше, а чёрных колец на графике меньше. Оставшиеся ошибки сидят в основном в зоне пересечения лун, где из-за `noise=0.15` классы реально перемешаны и идеальной границы не существует.

`train(network, epochs=30)` проходит тот же цикл: MSE, SGD с шагом 0.03, обнуление градиента, прямой проход, `backward`, `step`. `squeeze(1)` по-прежнему нужен, потому что последний слой выдаёт `(B, 1)`.

Сравнение двух печатных строк честное только если линейную модель уже обучили в предыдущей ячейке и имя `linear_accuracy` живо. Сеть не дообучает линейную модель: это второй, отдельный набор весов.

# Вопросы и развёрнутые ответы

### 1. Чем список отличается от кортежа?

Список изменяемый: `append`, замена по индексу, удаление. Кортеж после создания нельзя изменить. Оба упорядочены, оба индексируются с нуля, оба могут хранить разные типы. Кортеж хешируемый, если хешируемы его элементы, поэтому он может быть ключом словаря. Список ключом быть не может. Кортеж выбирают для фиксированной пары, например координаты точки или карты `(достоинство, масть)`.

### 2. Почему в срезе `numbers[1:3]` нет элемента с индексом 3?

Правая граница исключается. Так длина среза равна разности границ, и соседние срезы `a[:k]` и `a[k:]` стыкуются без общего элемента и без дырки. Индексация при этом всё равно с нуля.

### 3. Что будет при `config["нет_такого_ключа"]` и чем это отличается от `in`?

Чтение отсутствующего ключа поднимает `KeyError`. Оператор `in` ключ не читает, а только проверяет наличие и возвращает `True` или `False`. Для значения по умолчанию есть метод `get(ключ, запас)`.

### 4. Зачем запятая в `(42,)` и в форме `(100,)`?

Скобки сами по себе группируют выражение. Кортеж создаёт запятая. `(42)` — это число 42. `(42,)` — кортеж из одного числа. То же с формой тензора: `(100)` не является кортежем размера, а `(100,)` — форма одномерного тензора длины 100.

### 5. Чем `=` отличается от `==`?

`=` записывает значение в имя. `==` сравнивает и возвращает `True` или `False`. В условии `if` нужно `==`. Путаница `if x = 5` в Python является синтаксической ошибкой.

### 6. Как работают `range`, `enumerate` и `zip`?

`range(3)` даёт 0, 1, 2. `range(2, 14, 3)` даёт 2, 5, 8, 11: старт, стоп не включая, шаг. `enumerate` добавляет номер к элементу. `zip` идёт по нескольким последовательностям параллельно и останавливается на самой короткой.

### 7. Зачем `with`, если файл можно закрыть вручную?

`close()` не выполнится, если между `open` и `close` возникнет исключение. `with` вызывает выход из контекста в любом случае: нормальный конец блока, `return`, ошибка. Тот же протокол у `torch.no_grad()`: режим градиентов восстанавливается даже при ошибке внутри блока.

### 8. Что такое `self` и кто его передаёт?

`self` — первый параметр метода, ссылка на тот объект, у которого метод вызвали. При `my_dog.bark()` интерпретатор сам подставляет `my_dog` в `self`. В списке аргументов вызова его нет. Имя `self` — соглашение, механизм завязан на позицию первого параметра, но другие имена путают читателя.

### 9. Что сделает отсутствие `super().__init__()` в наследнике `nn.Module`?

Не будет инициализирован внутренний контейнер подмодулей и параметров. Присваивание `self.layer = nn.Linear(...)` может упасть или не зарегистрировать слой. Тогда `parameters()` будет пустым, оптимизатор не увидит веса, `to(device)` их не перенесёт, обучение не произойдёт. Поэтому первая строка конструктора модели — `super().__init__()`.

### 10. Почему слои создают в `__init__`, а не в `forward`?

Конструктор выполняется один раз. Веса живут вместе с объектом и обновляются оптимизатором. Если создать `nn.Linear` внутри `forward`, каждый прямой проход получит новый слой со случайными весами. Градиент предыдущего шага будет относиться уже к выброшенному объекту.

### 11. Почему вызывают `model(x)`, а не `model.forward(x)`?

`nn.Module.__call__` делает служебную работу: хуки до и после прохода, учёт режима. `forward` содержит только формулы. Обычный пользовательский вызов идёт через круглые скобки на объекте.

### 12. Зачем ReLU, если линейный слой уже умеет взвешивать входы?

Композиция линейных функций линейна: два слоя без активации можно переписать одним слоем. ReLU — нелинейная функция `max(0, z)`. После неё следующая линейная комбинация уже не сводится к одной гиперплоскости. На лунах это видно напрямую: одна прямая луны не разделяет, сеть с ReLU разделяет кривой.

### 13. Что возвращают `__len__` и `__getitem__` и кто их вызывает?

Их вызывает не пользовательский цикл напрямую, а `DataLoader`. `__len__` сообщает число примеров, по нему считается число пакетов. `__getitem__(idx)` возвращает один пример. В учебном классе это кортеж `(признаки, метка)`. Загрузчик собирает список таких кортежей и склеивает их в пакетные тензоры.

### 14. Чем опасно `shuffle=True` на проверочной выборке и зачем оно на обучающей?

На обучении перемешивание не даёт пакету всегда состоять из одних и тех же соседних точек. Градиент каждого шага становится менее однообразным. На проверке метрика — среднее по всем точкам, порядок суммирования на результат `mean` не влияет. Перемешивание проверки не запрещено, но смысла не имеет. В коде оно включено только у `train_loader`.

### 15. Объясните длину и наклон в задании 1 на числах `(1, 1)` и `(4, 5)`.

`dx = 3`, `dy = 4`. Длина `hypot(3, 4) = 5`, после округления `5.00`. Наклон `4/3 = 1.333...`, `round` даёт `1.33`. Это тангенс угла наклона. Знак наклона показывает, растёт прямая или падает слева направо. Здесь обе разности положительны, отрезок идёт вверх и вправо, наклон положителен.

### 16. Почему при `dx == 0` возвращается `None`, а не большое число?

Угловой коэффициент — это `dy/dx`. При `dx = 0` прямая вертикальная, угла с конечным тангенсом нет. Деление на ноль не является корректным ответом задачи. `None` явно говорит вызывающему коду: числа нет. Длина при этом существует: вертикальный отрезок имеет длину `|dy|`.

### 17. Почему карта хранится кортежем, а колода — списком?

Карта не меняется, кортеж это гарантирует и остаётся компактной парой. Колода меняется: `shuffle` переставляет элементы, `pop` удаляет карту. Список для этого подходит. Кортеж колоды нельзя было бы перемешать на месте.

### 18. Как из четырёх мастей и тринадцати достоинств получается ровно 52 уникальные карты?

Включение `for suit in suits for rank in ranks` — декартово произведение. На каждую из 4 мастей приходится каждый из 13 рангов. Повтор пары невозможен, потому что пара `(ранг, масть)` определяется обоими полями, а во внешних списках повторов нет. `shuffle` уникальность не ломает, он меняет только порядок.

### 19. Как считаются очки туза и почему при выборе 11 к сумме прибавляется 10, а не 11?

Сначала каждый туз уже учтён как `+1` строкой `total += aces`. Одиннадцать — это эта единица плюс ещё десять. Если прибавить 11, туз окажется учтён дважды и даст 12. Для дилера то же правило, только решение автоматическое: подъём делается, пока `total + 10 <= 21`.

### 20. Чем ход дилера отличается от хода игрока в коде?

Игрок управляется циклом `while True`, вопросом `choose` и условием `points >= 21`. Его тузы считаются с `player=True`. Дилер не спрашивается. После того как игрок не перебрал, цикл `while dealer.score() < 17` добирает карты. Тузы дилера поднимаются сами. Если игрок уже больше 21, ветка дилера не выполняется: ставка проиграна сразу.

### 21. Какие случаи исхода раунда есть и как меняются фишки?

Перебор игрока: фишки уменьшаются на ставку, дилер не добирает. Дилер перебрал или у игрока больше очков: фишки увеличиваются. У дилера больше очков и он не перебрал: фишки уменьшаются. Равенство: фишки не меняются. Ставка не может быть вне отрезка от 1 до текущего банка, это проверяет `isdecimal` вместе с двойным сравнением.

### 22. Чем `torch.empty` отличается от `torch.zeros`?

`zeros` записывает нули. `empty` только резервирует память, биты остаются какими были. Читать `empty`-тензор как данные нельзя. Его используют, когда следующая операция всё равно заполнит каждый элемент, например `fill_` или `copy_`.

### 23. Что означает подчёркивание в конце `exp_`, `add_`, `zero_`, `t_`?

Это соглашение PyTorch: операция пишет результат в вызывающий тензор и обычно возвращает его же. Версия без подчёркивания выделяет новый тензор. Путаница опасна: после `y = x.exp_()` имена `x` и `y` делят память, запись в одно видна через другое.

### 24. Чем `y = x` отличается от `y = x.clone()`?

Первое добавляет второе имя тому же объекту. `x is y` истинно. Второе копирует значения. Изменение копии не меняет исходный тензор. `copy_` — третий вариант: копировать данные в уже существующий буфер.

### 25. Чем `view` отличается от `transpose` и от `reshape`?

`transpose` меняет порядок осей и шаги, элементы в памяти обычно остаются на местах, поэтому соседние в новой матрице числа не обязаны быть соседними в памяти. `view` заново нарезает элементы в текущем порядке обхода и требует подходящих шагов, копии не делает. Поэтому `t()` и `view` одной итоговой формы дают разные матрицы, это показано на матрице `[[0,1,2],[3,4,5]]`. `reshape` ведёт себя как `view`, когда так можно, и копирует данные, когда шаги мешают.

### 26. Что такое stride?

Шаг оси — расстояние в элементах между `a[i]` и `a[i+1]` по этой оси. У строки матрицы `2×3` в плотном порядке шаги `(3, 1)`. У транспонированной матрицы шаги меняются. Непрерывность означает, что обход формы идёт по памяти без дыр. `contiguous()` восстанавливает такой порядок копированием, если его нет.

### 27. Почему время GPU измеряют только после `torch.cuda.synchronize()`?

Запуск ядра на GPU асинхронный. `a.mm(b)` возвращает управление, когда работа поставлена в очередь, а не когда умножение завершилось. `perf_counter` без ожидания засечёт постановку в очередь и почти не засечёт сам счёт. `synchronize` блокирует процессор, пока видеокарта не закончит ранее запущенные операции этой нити.

### 28. Почему третий замер с `transfer=True` может быть медленнее чистого GPU?

В него входит копирование двух матриц 1024×1024 из оперативной памяти в видеопамять и копирование результата обратно. Шина между CPU и GPU узкая относительно скорости чипа. Если матрицы каждый раз приезжают заново, транспорт сравним с полезной работой или больше неё. В обучении поэтому веса живут на GPU постоянно, а по шине ездит только очередной пакет.

### 29. Чем `memory_allocated` отличается от `memory_reserved` и что делает `empty_cache`?

`memory_allocated` — память живых тензоров. `memory_reserved` — блок, который аллокатор PyTorch удержал у CUDA, чтобы быстро выдавать следующие тензоры без запроса к драйверу. `empty_cache()` возвращает неиспользуемый резерв драйверу. Объекты, на которые ещё есть ссылки, остаются. Это не замена удалению тензора: чтобы освободить память тензора, нужно потерять на него все ссылки.

### 30. Что такое данные «две луны» и почему на них сравнивают линейную модель с сетью?

`make_moons` строит две дуги в двумерной плоскости, метки 0 и 1. При `noise=0.15` дуги слегка зашумлены. Классы нельзя честно отделить одной прямой, но можно отделить гладкой кривой. Линейная регрессия умеет только прямую. Сеть со скрытыми слоями умеет кривую. Разница точностей и картинки ошибок как раз это демонстрируют. Это не таблица химических измерений, а стандартный учебный набор для границы классов.

### 31. Почему метки переводят в `float32`?

`nn.Linear` считает в `float32`. `MSELoss` вычитает прогноз и метку. Типы должны совпасть. Целый тензор меток для этой формулы не подходит по типу, поэтому `type_as` делает вещественные 0.0 и 1.0. Содержательно класс не становится «наполовину классом»: ноль и единица остаются двумя целевыми числами регрессии.

### 32. Почему в задаче классификации стоит `MSELoss`, а не кросс-энтропия?

Формулировка задания — линейная **регрессия**, обученная градиентным спуском, на данных с метками 0 и 1. MSE сравнивает числовой прогноз с числовой меткой. Это осознанно простая постановка. Кросс-энтропия и `BCEWithLogitsLoss` были бы естественнее для вероятности класса, они работают с логитами и не требуют порога 0.5 вручную. В этой работе их нет, и на защите нужно говорить именно про MSE: среднее квадратов отклонений прогноза от 0 или 1.

### 33. Расшифруйте одну итерацию цикла обучения.

Берётся пакет признаков и меток и переносится на устройство. `zero_grad` стирает старые производные. Прямой проход считает прогноз. `squeeze(1)` выравнивает форму `(B, 1)` к `(B,)`. MSE даёт скаляр. `backward` заполняет `.grad` у веса и смещения по цепному правилу. `step` вычитает `lr * grad` из параметров. Следующий пакет идёт уже с новыми весами.

### 34. Что будет, если убрать `optimizer.zero_grad()`?

Градиенты начнут копиться. Градиент второго пакета прибавится к градиенту первого. Шаг станет слишком большим и будет зависеть от того, сколько пакетов уже прошло, а не только от текущего. Обучение разъедется или будет идти в сторону суммы случайных пакетов. Обнуление ставят **до** `backward` текущего шага. Ставить его после `step` тоже можно, но стандартное место — перед новым прямым и обратным проходом.

### 35. Зачем `squeeze(1)`?

`Linear(..., 1)` сохраняет ось выхода. Пакет из `B` точек даёт форму `(B, 1)`. Метки имеют форму `(B,)`. Две разные формы в поэлементной операции приводятся правилами broadcasting. Ось длины 1 умеет растягиваться, и сравнение может превратиться в таблицу всех пар «прогноз i с меткой j», а не в B отдельных ошибок. `squeeze(1)` удаляет фиктивную ось. `squeeze()` без аргумента снял бы все оси длины 1; явный номер оси безопаснее.

### 36. Как из прогноза получается класс и что такое доля верных ответов?

Если прогноз `>= 0.5`, ставится класс 1, иначе 0. Порог лежит посередине между целевыми значениями регрессии. Доля верных ответов — число совпадений с истинными метками, делённое на число проверочных точек. Считается она на отложенных данных, которые в `train` не попадали. `item()` нужен, чтобы из тензора из одного числа получить обычный `float` для печати.

### 37. Почему проверка обёрнута в `model.eval()` и `torch.no_grad()`?

`eval` переключает модули вроде Dropout и BatchNorm на поведение проверки. В этой сети таких модулей нет, вызов стоит для правильной привычки и для совместимости, если модель позже усложнится. `no_grad` отключает запись графа. На проверке веса не меняются, хранить узлы для `backward` — лишняя память и время. Без `no_grad` числа точности совпали бы, но каждый проход строил бы граф.

### 38. Сколько параметров у линейной модели и у сети и что это значит?

Линейная модель: 2 веса и 1 смещение, всего 3. Сеть: первый слой `2*16+16 = 48`, второй `16*16+16 = 272`, выход `16*1+1 = 17`, вместе 337. Все они есть в `model.parameters()` и обновляются одним SGD. ReLU параметров не добавляет. Большее число параметров само по себе не гарантирует лучшее качество. Здесь качество растёт, потому что появляется нелинейность, а не потому что «чисел больше».

### 39. Почему увеличение числа эпох не сделает линейную модель такой же точной, как сеть?

Семейство функций линейной модели — гиперплоскости. Ни один набор из трёх коэффициентов не отделяет две дуги. Градиентный спуск ищет лучшую прямую внутри этого семейства и останавливается на ней. Сеть — другое семейство функций. Сравнение на графике ошибок: у прямой ошибки образуют целые дуговые куски, у сети остаются в основном точки в шуме на стыке классов.

### 40. Где в задании 4 используются принципы из начала ноутбука?

`train` — обычная функция с параметрами `model` и `epochs`. Одна и та же функция обучает и `nn.Linear`, и `nn.Sequential`: вызывающему коду достаточно, что у объекта есть `parameters`, `train` и вызов как у функции. Это полиморфизм на общем интерфейсе `nn.Module`. `Sequential` наследует `nn.Module`, поэтому у него есть `to`, `train`, `eval`, `parameters`. Данные собраны в `TensorDataset`, где спрятаны `__len__` и `__getitem__`. Цикл `for features, labels in train_loader` — тот же `for` и распаковка кортежа, что в начале ноутбука.

### 41. Что фиксируют `torch.manual_seed(42)` и `random_state=42`?

`manual_seed` фиксирует генератор PyTorch: начальные веса `Linear` и операции вроде `rand` повторяются. `random_state` в `make_moons` и в `train_test_split` фиксирует генератор NumPy, которым пользуется sklearn: те же точки и то же разбиение 75/25. Это разные генераторы. Одинаковое число 42 их не связывает, просто оба источника случайности закреплены, и эксперимент можно повторить.

### 42. Что такое пакет, эпоха и шаг оптимизатора в числах этого опыта?

Обучающих точек 3750, размер пакета 64. На эпоху приходится 59 шагов оптимизатора, последний пакет короче. Эпох 30, значит вес обновляется примерно `59 * 30` раз. Каждый шаг смотрит только на свой пакет, а не на всю выборку сразу. Это и есть стохастический градиентный спуск: градиент шумный, зато шаг дешёвый. Полный градиент по всем 3750 точкам на каждом обновлении здесь не считается.

### 43. Может ли доля верных ответов на проверке быть хуже, чем кажется по обучению, и смотрит ли этот код потери обучения?

Функция `train` потери не печатает и не сохраняет. Она только обновляет веса. `accuracy` смотрит исключительно на проверочные точки. Поэтому в выводе нет отдельной обучающей точности. Если бы она была намного выше проверочной, это был бы признак переобучения. На этих лунах и при 30 эпохах маленькая сеть обычно обобщает нормально, потому что форма классов простая, а шум умеренный.

### 44. Что делает логическая индексация `val_X[errors, 0]`?

`errors` — булев вектор длины проверочной выборки. Запись `val_X[errors]` оставляет строки с `True`. Добавка `, 0` выбирает первый столбец этих строк. Так на график попадают абсциссы только ошибочных точек. Второй `scatter` рисует их пустыми кольцами поверх уже нарисованных цветных точек истинного класса.

### 45. Какой ответ дать, если спросят «что вы сделали своими руками»?

Своими руками собраны четыре вещи. Класс `DotCalculator`: разности координат, длина через `hypot`, наклон с защитой от деления на ноль, округление до двух знаков. Блэкджек: колода на 52 карты, рука, подсчёт очков с разным правилом туза для игрока и дилера, цикл ставки и раунда. Линейная регрессия: разбиение лун, тензоры, пакеты, `MSELoss`, SGD, цикл с `zero_grad` / `backward` / `step`, порог 0.5, график ошибок. Полносвязная сеть из двух скрытых слоёв по 16 нейронов с ReLU, обученная той же функцией `train` на тех же данных, с сравнением доли верных ответов.

Краткий вывод для конца ответа: линейная модель — это одна прямая в плоскости двух признаков, сеть за счёт ReLU строит кусочно-линейную границу и поэтому на двух лунах ошибается меньше. Оба обучения — минимизация средней квадратичной ошибки стохастическим градиентным спуском.
