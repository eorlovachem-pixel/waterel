# Готовые воспроизводимые задания для ещё не представленных стехиометрий

**Снимок состояния:** 30 октября 2026 года. **Дедлайн статьи:** 30 ноября 2026 года.

**Что внутри:** 17 подготовленных наборов исходных координат для **Li+ с n=7–14 и K+ с n=6–14**, единственный общий скрипт, который запускает авторские **GWH**, **CoCoS**, **MDAtomLocalEnvironment** и программу **xTB**, контроль исходных данных и будущих результатов, учёт версий кода, заготовки для структурного анализа и таблиц статьи.

**Важное ограничение:** никаких новых квантово-химических расчётов в данном архиве пока **нет**. Доступная вычислительная среда не имеет исполняемого `xtb` и доступа для скачивания GitLab. Файлы `.vecfle` — настоящие, взяты из предоставленного `vecfle.zip`; будущие `.xyz`, `energies.csv` и картинки будут созданы **только после подлинных расчетов**. Исходные данные других исследователей не выдаются за твою работу.

## Установка, один раз

На Windows используй WSL2 Ubuntu. На Linux аналогично. Нужно: Python 3.11+, NumPy, SciPy, Matplotlib, Git и `xtb`. Пример с уже установленной `conda`:

```bash
conda create -n hydrates -c conda-forge python=3.11 numpy scipy matplotlib xtb -y
conda activate hydrates
xtb --version
python -c 'import numpy, scipy, matplotlib;print("OK")'
```

Распакуй архив и открой терминал Ubuntu внутри папки архива:

```bash
cd ~/Hydration_unassigned_2026-10-30
bash setup_vendors.sh
```

Команда скачает открытые исходные репозитории автора GWH, CoCoS, MDAtomLocalEnvironment; их версии фиксируются при запуске. **Не изменяй общий исходник GWH сама, пока не подтверждён согласованный вариант ZYZ** — разные участники должны использовать одинаковый метод.

## Как провести одну стехиометрию полностью (пример Li_07)

**0. Пробный запуск в отдельной папке** — одна или две структуры, без риска затереть основную серию:

```bash
python workflow.py gwh --case Li_07 --pilot --nstruct 2
python workflow.py collect --case Li_07 --pilot
python workflow.py prepare --case Li_07 --pilot
python workflow.py relax --case Li_07 --pilot --workers 1 --limit 1
python workflow.py relax --case Li_07 --pilot --workers 1
python workflow.py dedup --case Li_07 --pilot
```

Папка пилота `pilots/Li_07/`. Не переносите пилотные результаты в основную серию, пока не проверены версия кода, согласованность ZYZ и энергетические логи. Число структур после пробного запуска не является научным результатом поиска.

**1. Настоящая первая стадия — GWH, 100 начальных структур.**

```bash
python workflow.py gwh --case Li_07 --nstruct 100
```

Команда автора в основе запуска: `gloriouswaterhole.py -f ... --Charge 1 --NumStruct 100 --Random --Opt --AddMethod " --alpb water --gfn 2 " --DoNotCenter`. Результаты находятся в `cases/Li_07/gwh/gwh_opt_str0000...`.

**2. Проверить GWH и собрать исходные геометрии:**

```bash
python workflow.py collect --case Li_07
python workflow.py prepare --case Li_07
```

Скрипт требует для всех 100 `mol_strXXXX_fin.xyz`, подтверждения нормального завершения xTB в `qc_tmp.err`, верной формулы и энергии `E = ... Eh`. Затем составляет `cases/Li_07/source/constrained_multiframe.xyz`, `energies.csv` и `cases/Li_07/xtb_runs/frame_XXX/input.xyz`. Если ошибки, список будет в `cases/Li_07/collect_report.json`.

**3. Свободная оптимизация ВСЕХ 100 геометрий GFN2-xTB/ALPB(water), без фильтрации CoCoS до неё:**

```bash
python workflow.py relax --case Li_07 --workers 1 --limit 1
python workflow.py relax --case Li_07 --workers 2
```

Результаты отдельных задач — `xtb_runs/frame_XXX/xtb.out` и `xtbopt.xyz`. Если процесс остановится, скрипт сможет пропустить уже проверенно завершённые задачи. На больших кластерах может потребоваться много времени и памяти; начни с `--workers 1`. Настоящие расчёты нужно запускать на компьютере с `xtb`.

**4. После проверки завершения всех 100 запусков — фильтрация CoCoS и MDAtomLocalEnvironment:**

```bash
python workflow.py dedup --case Li_07 --mdatom vendors/MDAtomLocalEnvironment/atom_local_environment_computer.py
```

Выходы: `cases/Li_07/xtb_runs/postprocess/` с `all_freely_optimized.csv`, `rank_shift_constrained_vs_unconstrained.csv`, `free_sorted_for_cocos.xyz`, `unique_representatives.csv`, `unique_lowest_energy_representatives.xyz`, логом CoCoS, результатами MDAtomLocalEnvironment. По умолчанию в пакете используется пользовательский снимок `cocos.py`; если Денис выдал исправленную проверенную версию, передай её путь опцией `--cocos` и запиши версию.

**5. Проверка устойчивости CoCoS к настройкам:**

```bash
python check_cocos_robustness.py --case Li_07
```

Проверяет варианты начальных случайных поворотов и числа начальных проб. При разных итоговых классах результат нельзя считать окончательно подтверждённым, пока не выяснена причина.

**6. Результаты для статьи по завершённым случаям:**

```bash
python workflow.py aggregate
```

Получатся сводная таблица `aggregate_results/completed_cases_summary.csv` и рисунки количества найденных уникальных конформеров от `n` по каждому иону. График **не сравнивает непосредственно полные энергии кластеров с разным количеством воды**.

## Методологические условия

- Для единого сравнения сохраняем GFN2-xTB + ALPB(water), заряд +1, одинаковую версию GWH, включая исправление ZYZ, и одинаковые параметры CoCoS (различия документируются).
- После ограниченного GWH **не удаляем дубликаты** и не применяем энергетическое окно.
- Свободно оптимизируем каждую корректную исходную структуру.
- Сравниваем геометрии CoCoS только после свободной релаксации, затем выбираем низкоэнергетические в пределах одной стехиометрии.
- MDAtomLocalEnvironment выдаёт показатели локального окружения; не следует автоматически приравнивать его эффективную `#water` к строгому целочисленному координационному числу без установленного критерия.
- Вычисленный минимум является кандидатом в локальный минимум; при необходимости проверить частоты и высокоуровневый метод на избранных структурах.
- Относительные **электронные** энергии между разными `n` нельзя сравнивать напрямую как энергии гидратации или свободные энергии в растворе.

## Как получить научный вклад

Проводить собственные действительные вычисления и сохранять исходные файлы, вести таблицы и проверки, вручную исследовать спорные пары CoCoS, анализировать изменения энергетического порядка после свободной релаксации, писать собственную часть разделов *Computational Methods* и *Results and Discussion* и согласовать авторство заранее. Просто сформировать набор команд для будущего расчёта недостаточно для соавторства.

## Один запуск полного протокола после согласования с Денисом

Если пилот уже прошёл, актуальный GWH/CoCoS согласован и случай **закреплён именно за тобой**, можно вместо пошаговых команд запустить всё одной командой:

```bash
bash RUN_ONE_APPROVED_CASE.sh Li_07
```

Не запускай этот скрипт сразу для всех 17 систем: 100 начальных GWH оптимизаций плюс 100 полных свободных оптимизаций на каждую стехиометрию — это большой объём вычислений. При прерывании GWH или неполных исходных файлах сначала проверяй логи; архивирование и перезапуск не должны перезаписывать уже имеющиеся корректные данные.
